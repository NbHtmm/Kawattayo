# テスト追加時の手順

1. [テスト規約](../TESTING.md) と [実行・拡張手順](README.md) を読む。
2. UTはソース1ファイルに対応する `*.Tests.cs` へ追加し、対象の関数と期待結果をテスト名から分かるようにする。
3. SCTは [試験仕様](SCT/SPEC.md) に利用者の目的、前提、手順、期待結果を書く。配布EXEを起動し、外から観測できる結果を検証する。仕様・自動試験・結果に同じケースIDを使う。手動ケースを自動の合格に含めず、製品にテスト専用モードを足さない。
4. 同じ修正で、正常系・境界・関連する失敗時の副作用を確かめる。テスト用のデータ・設定・プロセスを通常環境から分離する。
5. `run_ut.bat` と変更に対応する `run_sct.bat` を実行し、成功数、失敗や未確認の範囲、必要に応じZIPのSHA-256を報告する。ファイル対応数を関数カバレッジと呼ばない。
6. 全関数の台帳やGUIの自動操作が未導入である間は、その検証をしたことにしない。
