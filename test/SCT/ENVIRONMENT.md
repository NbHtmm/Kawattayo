# 専用環境が必要なSCTの実施手順

このページは未実施項目を引き継ぐための手順書です。実施結果ではありません。テスト用Windowsセッションと使い捨てのファイルだけを使い、通常の設定・データ・ネットワークを変更しないでください。

## 共通の記録

1. 配布ZIPをケースごとに別の空フォルダへ展開し、ZIPのSHA-256、Windowsのバージョン、試験日時、ケースIDを記録する。
2. 表の前提がそろわなければ「環境不足」で止める。完了した操作、観測した値、期待との差、必要に応じて画面やログを保存する。
3. 結果は自動SCTの `result.json` とは別に保存し、未実施をPASS扱いしない。通常の共有フォルダ、通知設定、関連付けを変更しない。

| ケース | 専用の前提・操作 | 合格条件と証跡 |
|---|---|---|
| SCT-GUI-003 | 通知が有効な試験セッションで差分収集を開き、比較結果を保持したまま監視ファイルを変更。表示された通知を押す。 | 監視ウィンドウを開き、別の差分収集ウィンドウと比較状態を維持。通知・操作直後の画面を残す。 |
| SCT-GUI-007 | 使い捨てWindowsユーザーで試験用ビューアーを関連付け済みにする。監視中の試験文書を更新し、「ダウンロードして開く」を選び空の保存先を指定する。 | ビューアーの記録が収集先の絶対パスを指し、元のパスを受け取らない。コピー元・先のSHA-256が一致し、元は変更されない。 |
| SCT-GUI-015 | 専用の対話セッションで、エクスプローラーの試験フォルダからファイルとフォルダを設定画面にドロップする。同じ対象を再ドロップする。 | 正しい種類で各1件。設定JSONで最初の登録IDを控え、再ドロップ後も同じIDと件数を確認する。 |
| SCT-NOTIFY-001 | 通知を記録できる試験セッション。安定待ちを長めにし、同じ文書を短時間に2回更新。安定後、未読のまま再更新し、再通知のオン・オフを別の展開先で比較する。 | 安定中のバナーは0件。安定後に最初の通知が1件。未読の再更新時は設定オンのみ通知。更新とバナーの時刻・件数を記録する。 |
| SCT-SMB-001 | 破棄可能な試験専用共有と2台のクライアント。Aだけアクセス不能にし、Bで文書を更新後、Aを戻す。 | Aの不達を消失と誤判定せず、復旧後にBの実際の変更のみ検知。A・Bのログと対象の更新履歴を保存する。 |
| SCT-SMB-002 | 別の試験専用共有でAが繰り返し監視している間に、Bで試験ファイルへ書き込み、改名、削除を順に実施する。 | Bの操作がAの監視によるロックで失敗しない。Aは照会が完了した時点で正しい状態になる。Bの操作成否とAの履歴を記録する。 |
| SCT-SMB-003 | 専用のUNC共有に到達可能・権限不足のフォルダと、日本語名・想定上限内の長いパスを用意する。実際に存在しない対象とも比較する。 | 通常の対象は照会でき、権限不足は確認不能として表示し、到達可能だが存在しない対象と混同しない。対象パスと判定を記録する。 |
| SCT-PERF-001 | 専用PCでファイル件数・階層・保存位置・許容応答時間を事前に記録し、段階的に増やす。監視中に設定を開き、中断・再開する。 | 設定表示と中断が事前の目標時間内。再開後の件数は用意した一覧と一致し、履歴欠落がない。経過時間・件数・対象PCの条件を残す。 |
| SCT-DPI-001 | 使い捨てセッションで4Kと異なる倍率の画面を用意し、画面間の移動・最小幅への縮小・文字サイズ変更を行う。 | ファイル名、フォルダ種別、展開・既読の操作が確認でき、クリック対象がずれず、必要時にスクロールできる。解像度・倍率別の画面を保存する。 |

## SCT-SMB-002 の補助スクリプト

`Run-SmbLifecycle.ps1` は自動SCTとは別に起動する。2台の検証用Windows端末が同じ**試験専用**共有にアクセスできることを先に確認し、`\\SERVER\SHARE\Kawattayo-Sct` を空で用意する。通常のアプリは開いていない専用セッションを使う。既存のアプリを終了させたり共有設定を変更したりする機能はない。PowerShell 7を使い、両端末に同じ試験コードを置く。

1. 両端末に同じ新しい実行ID（`[guid]::NewGuid()`）を用意する。端末Aで `pwsh -File test/SCT/Run-SmbLifecycle.ps1 -Role Monitor -FixtureRoot "\\SERVER\SHARE\Kawattayo-Sct" -RunId "<同じID>" -Package "<配布ZIP>" -DedicatedShare`。
2. Aに `Fixture is ready for Writer` が出たら45秒以内に、Bで `pwsh -File test/SCT/Run-SmbLifecycle.ps1 -Role Writer -FixtureRoot "\\SERVER\SHARE\Kawattayo-Sct" -RunId "<同じID>" -DedicatedShare`。2台はそれぞれ固有のコンピューター名を使用する。
3. AがBの排他書き込み中に監視を1回終え、Bが書き込みを完了できることを確認する。続いてBがファイルを改名、元の名前に戻す、削除を行い、Aで「更新」「消失」「出現」「消失」が順に各1件だけ検知されることを確認する。結果はAの `build/SMB-002-*/environment-result.json` に別保存する。A・Bのコンソールログも残す。
4. `-LocalRehearsal` は同一端末のリポジトリ内 `build/` 配下の使い捨てフォルダで手順を予行するモード。成功しても `REHEARSAL_PASS` で、実SMBの合格には含めない。試験用の共有側フォルダは自動で削除しない。

## SCT-PERF-001 の計測スクリプト

専用の対話型Windowsセッションでアプリを閉じ、件数・上限を先に決めてから `pwsh -File test/SCT/Run-PerfSession.ps1 -Package "<配布ZIP>" -Files 16000 -MaxUiMilliseconds 2000 -DedicatedSession` を実行する。100件ずつに分けた作業用のローカルフォルダと設定を毎回新規作成する。監視中と表示されたところで設定表示と中断を別々に測定し、再開後の総件数（指定件数＋1）と未読のファイル名まで検証する。測定に必要な監視中の状態が観測できなければ `BLOCKED` とし、平常時の応答時間で代用しない。

時刻・件数・上限・測定値・ZIPのSHA-256は `build/PERF-001-*/environment-result.json` に保存する。上限は使用先で合意した値を指定し、別の端末やネットワークの性能をこの結果から保証しない。通常の設定や監視対象は変更しない。著しく少ない件数で手順を予行するなら `-DedicatedSession` の代わりに `-LocalRehearsal` を選ぶ。この結果は実環境の合格に含めない。

## SCT-GUI-003 の通知起動スクリプト

通知が使える使い捨てのWindowsセッションで、普段のアプリが起動していないことを確認し、`pwsh -File test/SCT/Run-NotificationActivation.ps1 -Package "<配布ZIP>" -DedicatedSession` を実行する。試験用の差分収集画面に未保存の入力を設定して監視画面を隠し、試験ファイルを更新する。案内が出たら、Windowsが出した新しい通知を人がクリックする。タスクトレイのアイコンやランチャーからは手動で開かない。

スクリプトは再表示された監視画面で、下位フォルダの対象行が選択され、差分収集画面と未保存の入力が残っていることを確認する。通知の画面証跡は別途残す。`-PrepareOnly` は試験データと配布物を用意するだけで、アプリも通知も起動しない。結果は `build/NOTIFY-GUI-003-*/environment-result.json`。予行や未実施は通知の合格に含めない。

## SCT-DPI-001 の画面確認スクリプト

`pwsh -File test/SCT/Run-DpiSession.ps1 -Package "<配布ZIP>" -InspectOnly` で画面数と解像度のみ確認できる。アプリの起動・画面キャプチャ・設定変更は行わない。実試験は4Kと倍率の異なるもう1台を接続した使い捨てセッションで、`-InspectOnly` を `-DedicatedSession` に替える。

案内に従い、試験用ウィンドウだけを指定の画面へ移動・縮小し、実際のポインターで長いファイル名の行を展開する。スクリプトがファイルの到達性、実際の画面ID・解像度、ウィンドウのDPIを確認する。ボタンやスクロールのヒット位置は利用者の確認が必要。証跡は `build/DPI-001-*/environment-result.json` と手動の検証画像。画面が1台、4Kなし、またはDPIが同じなら合格にしない。

## SCT-GUI-015 のエクスプローラー操作

使い捨ての対話セッションで `pwsh -File test/SCT/Run-ExplorerDrop.ps1 -Package "<配布ZIP>" -DedicatedSession`。案内に出る試験用フォルダをエクスプローラーで開き、指定のファイルとフォルダを実際にドラッグ＆ドロップする。同じ操作をもう一度行う。スクリプトは設定画面、登録件数、設定ファイルのID・絶対パス・種類、実ファイルの内容を1回目と2回目で照合する。通常の対象やクリップボードは使わない。記録は `build/EXPLORER-GUI-015-*/environment-result.json`。`-PrepareOnly` の場合、配布物を展開するが実際の操作は行わない。

## SCT-GUI-007 の「ダウンロードして開く」

**通常アカウントでは行わない。** 使い捨てのWindowsテストアカウントで、次の手順を実施する。

1. `$id=[guid]::NewGuid()` を作り、`pwsh -File test/SCT/Run-DownloadAndOpen.ps1 -Package "<配布ZIP>" -RunId $id -PrepareOnly`。試験用のビューアーは渡された引数の記録だけを行う。既定の関連付けは変更しない。
2. 検証アカウントに限り、Windowsの設定で準備した `SctTextViewer.exe` を `.txt` の関連アプリにする。この操作はスクリプトでは行わない。次に、同じZIPと同じ実行IDで `-PrepareOnly` を `-DedicatedSession` に替える。準備した実行ファイルに解決できなければ、アプリを起動せずに止まる。
3. 指定の未読行を右クリックし「ダウンロードして開く」を選び、表示された空の試験用保存先を選ぶ。スクリプトはビューアーへ渡った先が元ファイルではなく保存先であること、元とコピーのSHA-256が一致することを確認する。記録先は `build/OPEN-GUI-007-*/environment-result.json`。

## SCT-SMB-003 のパスと権限の確認

試験専用の共有に `\\SERVER\SHARE\Kawattayo-Sct\Paths` を用意する。中の `readable\測定.txt` と、`readable` 配下の絶対パス長260文字以上の別ファイルはテストユーザーから読めるようにする。`readable\absent-file.txt` は作らず、`denied` は実在するが列挙権限を与えないフォルダにする。共有とACLを用意するのは専用環境の管理者で、スクリプトはそれらに書き込まない。

`pwsh -File test/SCT/Run-SmbPathChecks.ps1 -Package "<配布ZIP>" -FixtureRoot "\\SERVER\SHARE\Kawattayo-Sct\Paths" -LongRelativePath "<readable配下の相対パス>" -DedicatedShare`。試験用アプリの状態列が、Unicode名と長いパスは「正常」、存在しないファイルは「対象なし」、権限不足は「監視失敗」と区別されることを確認する。実サーバーに接続しない準備確認は `-DedicatedShare` の代わりに `-PrepareOnly`。記録は `build/SMB-003-*/environment-result.json`。
